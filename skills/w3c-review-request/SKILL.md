# Wide and horizontal review requests

Identify the stable revision to review, the requested feedback, relevant changes since the previous review and the available self-review results. Use each reviewing group's current request template and instructions. Keep issue links, responses, resolutions and outstanding disagreements traceable.

A general announcement is not evidence that a horizontal review was requested or completed. Do not equate silence with approval or mark a discipline irrelevant without evidence. Prepare the request and tracking material within the user's scope; only send it when authorized. Structural headings in respec-mcp cannot establish review completion.

## Shared guidance and tools

Read [Shared editorial principles](../../docs/EDITORIAL_PRINCIPLES.md) for native-language collaboration and the boundaries of automated checks. Use only tools applicable to this document: GitHub review templates, W3C horizontal issue tracker, Review dashboards.
