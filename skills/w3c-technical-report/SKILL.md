# Technical reports and specifications

Establish the intended audience, document type and actual maturity before changing boilerplate. Keep normative requirements distinguishable from explanation and examples. Use stable definitions and references, concrete conformance targets and testable behavior. Check semantic markup, readable examples and accessibility alongside prose.

Preserve the existing generator. ReSpec source can use respec_preflight and respec_validate; Bikeshed source requires Bikeshed's own build. Run the relevant HTML and link checks on generated output when required. A successful generator build does not establish publication readiness or complete standards conformance. For formal publication, use the publication skill and the selected W3C publication profile.

## Shared guidance and tools

Read [Shared editorial principles](../../docs/EDITORIAL_PRINCIPLES.md) for native-language collaboration and the boundaries of automated checks. Use only tools applicable to this document: ReSpec, Bikeshed, Nu HTML Checker, W3C Link Checker.
