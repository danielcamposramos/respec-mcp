# Internationalization self-reviews

Use the current i18n checklist and specification guidance. Examine text encoding, language and direction metadata, identifiers, normalization, layout and culturally variable data where the design touches them. Treat Unicode and language terminology precisely and reuse established definitions.

Provide examples beyond one locale, script or name convention. Record why a question is not applicable, rather than assuming an English document needs no internationalization review. Native-language discussion and English drafting can help authors participate, but do not themselves solve a feature's i18n requirements. Track unresolved issues and request expert review through the current process.

## Shared guidance and tools

Read [Shared editorial principles](../../docs/EDITORIAL_PRINCIPLES.md) for native-language collaboration and the boundaries of automated checks. Use only tools applicable to this document: W3C i18n short checklist, Internationalization review tracker.
